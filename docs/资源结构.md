# 资源目录与来源边界

通用构建工具读取已有的、使用者有权使用的 web 资源目录，不会自动搬运游戏素材。

目录需包含 catalog.js、models/*.js、resources/*、vendor/*，以及背景和对白索引。catalog 的每个成员包含 id、name、roman、band、groups、outfits；每套服装包含 id、name、script。角色使用同一 canonical id，多归属通过 groups 表示，不能为多个分组复制模型。

models 脚本赋值 window.loadedPetAsset；至少包含 key（角色ID/服装ID）、settings（旧 model.json 或新版 model3.json 内容与 url）、actions、voices、voiceInteractions。可选 interactionExpressions、mouthMeshes、presentation 等提供现有互动适配。旧文件引用 textures/motions/expressions/model，新格式引用 FileReferences.Textures/Motions/Expressions/Moc；相对资源路径以 settings.url 为基准。motions 的分组需包含 idle；具体可用动作由 actions 数组声明。

目录索引以及构建所得二进制资源需自行核对使用和再分发权限。空元数据只是结构占位，不是假模型。Live2D运行库需按实际版本从许可允许的来源获得。

背景图片使用976×596 WebP；切换时只保留当前背景。乐队Logo建议最大320×96 WebP，band-logos.js赋值 window.petBandLogos，键为分组名、值为Logo相对路径。无图片时使用文字入口。

通用构建工具验证基础目录和每个模型脚本存在，但不会替用户验证版权、所有贴图路径或所有模型在手机上的渲染效果。需按验收清单进行实测。
